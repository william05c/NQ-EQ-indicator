# Data: sources, coverage, and what was cleaned

Everything here is free and rebuildable with `node ../src/build_all_datasets.js`.
No API keys, no vendor account.

| File | Instrument | Coverage | Sessions | Endpoint |
|---|---|---|---|---|
| `nasdaq_composite_IXIC_daily_2002-2026.csv` | Nasdaq Composite index | 2002-01-01 → 2026-10-16 | 6,255 | `api.nasdaq.com/api/quote/COMP/historical` |
| `nasdaq_composite_IXIC_daily_2015-2026.csv` | Nasdaq Composite index | 2015-01-02 → 2026-10-16 | 2,965 | Tencent kline (`usIXIC`) |

Derived files (regenerated by the scripts):

| File | What it contains |
|---|---|
| `range_bands_oos.csv` | every out-of-sample forecast 2016–2026: predicted high/low bands vs actual, plus hit flags |
| `backtest_yearly.csv` | year, sessions, MAE vs naive, coverage |

All CSV files are `Date,Open,High,Low,Close[,Volume]`, one row per session, ascending.

## Session definitions — the most important caveat

| Instrument | Session | Mean daily range | Mean gap from prior close |
|---|---|---|---|
| ^IXIC | RTH 09:30–16:00 | 1.44% | 0.50% |
| NQ | **24-hour Globex** | **1.98%** | **0.14%** |
| ES | **24-hour Globex** | 1.40% | 0.17% |

The tiny gaps prove the futures bars include the overnight session: the overnight move sits
*inside* the bar rather than jumping the open. Consequences:

- NQ is a **harder target** (median error 0.43% vs 0.29% for the index) because it spans 24h.
- If your TradingView chart is RTH-only, use the cash-index profile rather than the NQ one.
- For a true RTH day-trading indicator, intraday bars are required — this is the one upgrade
  that matters (see [`05-limitations.md`](05-limitations.md)).

## Cleaning applied

**Index (Nasdaq endpoint).** The API occasionally returns placeholder rows on exchange holidays
with `open = high = low = 0` and the prior close as "close". Any row with a non-positive
open/high/low is dropped before writing.

**Futures (Sina).** Rows with `high == low` (flat placeholders) and duplicate dates are dropped:
190 rows for ES, 1 for NQ. Early ES history in particular contains long runs of flat
placeholders.

**Three sessions corrected.** On the Tencent feed, three sessions carried corrupt bars. They
were replaced with values on which the other two independent feeds (Eastmoney and
`api.nasdaq.com`) agree:

| Date | Was | Now | Corrupt field |
|---|---|---|---|
| 2015-01-21 | close 4678.89 | close 4667.42 | close |
| 2015-06-30 | close 4991.94, high 5020.71 | close 4986.87, high 5008.76 | close, high, low |
| 2016-06-27 | close 4636.50, low 4635.18 | close 4594.44, low 4574.25 | close, high, low |

Every other overlapping session matched to the cent across sources. The corrections are applied
in [`../src/refresh_ixic.js`](../src/refresh_ixic.js) and visible in git history.

## Quality checks that pass

- No duplicate dates, strictly ascending order.
- 250–253 sessions per full year; the largest calendar gap is 4 days (holiday weekend).
- No malformed or blank fields.
- OHLC internally consistent (`high ≥ max(open, close) ≥ min(open, close) ≥ low`).

## Provenance and reuse

The data is derived from public endpoints and is included for reproducibility. It is not
licensed from a vendor, and Nasdaq/Sina terms of use apply to their respective feeds. If you
plan to redistribute at scale, re-pull from the original endpoints rather than relying on the
snapshot committed here — or drop `data/` from version control and keep the fetch scripts.

## Refreshing

```bash
node ../src/build_all_datasets.js     # re-pull everything (~30 s)
node ../src/range_forecast.js         # refit + revalidate
node ../src/fit_coefficients.js       # new constants for the Pine port
```

`refresh_ixic.js` will extend the Tencent-sourced index file to the current date.
